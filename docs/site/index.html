Kwa · Kit · Workflow · Agents · v

Un kit de workflow
et d'agents.

Un socle de process de développement pour travailler avec des agents de code : règles, garde-fous, skills, mémoire et circuit de travail, les mêmes sur chaque projet. Ce qui change d'un projet à l'autre tient dans un fichier de politique.

Principes

Quatre idées,
pas plus.

Un noyau, des modules, une politique

Le noyau est commun. Les modules s'activent selon la stack détectée (monorepo, Prisma, Expo, Scaleway…). Tout le spécifique d'un projet vit dans .claude/kwa.policy.json, qui appartient au projet et n'est jamais écrasé.

Une source unique

AGENTS.md fait foi. CLAUDE.md n'est qu'un pointeur @AGENTS.md. Kwa n'écrit que dans son bloc balisé ; le reste du fichier reste au projet, octet pour octet.

Des filets, pas une prison

Les gardes attrapent la bévue : un cat .env, un push sur main, un rm hors du projet. Ils ne protègent pas contre un agent hostile ; pour cela, protection de branche GitHub et permissions.deny. Une erreur interne d'un garde demande à l'humain, jamais un passage silencieux.

Kwa ne touche jamais à git

Il n'ajoute, ne commite, ne pousse rien. Un fichier modifié à la main est sauvegardé avant d'être remplacé. Les gabarits GitHub sont copiés une fois, puis laissés au projet.

Chaque skill dit quand l'utiliser. L'étiquette indique ce dont elle s'inspire ; « Kwa » signifie une conception propre. Aucun texte n'est recopié : tout est réécrit en français et branché sur la politique du projet.

Mémoire

Chaque session enrichit
la suivante.

Super-board mémorise les constats d'une revue de PR. Aucun outil du lot ne fait remonter ce qu'une session a coûté à apprendre. Kwa le fait, sans rien écrire dans la documentation sans ton accord.

1. SessionAu fil du travail, une note rapide : kwa-memory capture gotcha "…"
2. DéclencheurEn fin de session substantielle (3 fichiers de code ou plus), une invitation unique. Silence sinon.
3. FiltreSeulement le non-dérivable du code et de git. Chaque affirmation est revérifiée.
4. TriChaque apprentissage est routé vers la bonne destination, avec le diff exact.
5. RepriseAu démarrage suivant, les notes en attente sont rappelées à l'agent.

Docs du projet

Décisions en ADR, pièges datés, conventions dans AGENTS.md. Versionné, lu par tout agent et tout collègue.

Base de connaissance

Transverse aux projets : capture rapide dans la boîte de réception de l'équipe (KWA_VAULT_INBOX), jamais dans un fichier protégé.

Accord requisUn tableau de sept lignes maximum est présenté avec les diffs. Rien n'est appliqué sans « tout », « 1 et 3 » ou « rien ». « Rien à capitaliser » est une réponse valable.

Méthode

Ce que superpowers apportait,
Kwa le porte.

Le module craft reprend les principes de discipline (lois de fer, signaux d'alerte, revues en deux temps), réécrits en français et branchés sur la politique du projet. Un rappel de routage est injecté au démarrage de session, limité aux skills réellement installées.

Remplacer l'existant

Remplacer un outillage maison,
Kwa le porte.

Beaucoup de projets ont déjà leur propre jeu de scripts : hooks shell par projet, skills de déploiement, règles de dépôt. Kwa les porte dans le noyau (générique) et dans la politique (spécifique). kwa doctor signale les doublons à retirer, une fois la politique validée. Les cas d'un harnais de test réel sont rejoués contre Kwa avec examples/expo-monorepo.policy.json.

Crédits
Le meilleur
de plusieurs mondes.

    
Kwa n'invente pas tout. Il assemble des idées éprouvées par d'autres, relues, réécrites et testées pour un flux par pull request. Chaque source est sous licence MIT ; les textes de licence sont dans licenses/.

  






  
Limites et suite
Ce qui reste
à faire.

  

  
Les gardes ne sont pas une frontière de sécurité
Un agent peut en théorie éditer ses propres hooks ; guard-write demande confirmation avant de toucher à .claude/kwa/ et settings.json, rien de plus. Pour une vraie barrière : règles de protection de branche GitHub et permissions.deny.

  
Les gardes analysent du texte
Un script écrit dans un fichier puis exécuté, ou une commande assemblée à l'exécution, échappent à l'analyse. Les cibles calculées ($(…), variables) déclenchent une demande plutôt qu'un passage.

  
Feuille de route
1. Essai sur un projet pilote, toujours en simulation d'abord. 2. kwa sync : installer sur tous les projets listés dans un fichier de configuration. 3. Packaging en plugin Claude Code (skills seulement ; les hooks passent par l'installeur). 4. Évals de skills avec claude plugin eval, à vérifier sur la version en place. 5. Fusion guidée d'un CLAUDE.md existant dans AGENTS.md, avec contrôle de couverture. 6. Profil « projet client » : compte machine, politique de fusion humaine.

  
Ce que Kwa ne décide pas pour toi
Le contenu de la politique d'un projet (commandes interdites, environnements, pré-vols) vient de tes incidents. Kwa pré-remplit ce qu'il peut déduire et te laisse le reste. Le module client-handover n'est jamais déduit : il dépend de l'intention.
